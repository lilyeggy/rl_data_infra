# V2.1 Live：真实服务器 Pi 实验（已归档）

> 状态：真实 Pi 0.84.2 已在容器云服务器运行 control/candidate 配对实验；模型按用户决策从
> `gpt-5.6-luna` 切换为 `deepseek-v4-flash`（区域不可用导致，不是 silent fallback）。

## 实验设定

```text
位置：海南容器云服务器（Ubuntu 24.04，104 vCPU）
Pi：0.84.2
模型：opencode-go / deepseek-v4-flash，thinking=minimal
工具：read, grep, find, ls
任务：3 个 synthetic filesystem 任务（missing-N.json 不存在，task-N.json 存在）
control policy：FILE_NOT_FOUND 后同一路径重试一次，然后停止
candidate policy：FILE_NOT_FOUND 后 find task-*.json，读唯一候选；无/多候选则停止
verifier：严格 exact JSON（task_id/status/failure_count），允许 code fence 一律失败
Gate：冻结 reference-v2 阈值（token ≤ +20%，latency ≤ +25%）
```

## 结果（两次运行）

| 指标 | run-1 | run-2（重跑） |
|---|---|---|
| control success | 0/3 | 0/3 |
| candidate success | 3/3 | 3/3 |
| OBSERVED_TOOL_ERROR_LOOP | 3 → 0 | 3 → 0 |
| token 增幅 | +11.79% | +12.12% |
| latency 增幅 | +41.45% | +472% |
| Gate | REJECT（latency） | REJECT（latency） |
| SFT candidates | 3 | 3 |
| on-policy RL | 0 | 0 |

两次 token 结果稳定（+12% 左右），latency 波动极大（+41% 与 +472%），说明延迟主要由
provider 侧方差主导，单次 3 对实验不足以稳定测量 +25% 延迟阈值。

## 模型行为证据（真实轨迹）

control（task-1）：

```text
read missing-1.json → ENOENT
read missing-1.json（相同参数）
→ 停止，无法回答 failure_count
```

candidate（task-1）：

```text
read missing-1.json → ENOENT
find task-*.json → task-1.json
read task-1.json → 文件内容
→ {"task_id":"task-1","status":"SUCCESS","failure_count":2}  ✅
```

## 踩到并修复的真实环境问题

1. **地域 403**：gpt-5.6-luna 在海南节点不可用；按用户决策切换 deepseek-v4-flash，并在
   ExperimentManifest.metadata 中记录“不是 silent fallback”。
2. **status 语义歧义**：deepseek 把 status 解释为“文件里是否有 FAILURE”，首轮 candidate
   0/3（恢复行为全部正确）。通过 prompt 澄清（非放宽 verifier/Gate）后 3/3。
3. **偶发慢速/多轮**：一次 candidate 240s 超时；同一 prompt 手动运行 60s 内正确完成。
   增加 `Use at most 4 tool calls total` 有界约束与 600s 超时后稳定。
4. **协议重复消息**：Pi NDJSON 中 tool call 在 message_end/turn_end/agent_end 重复出现，
   统计需按 canonical event 去重（adapter 已处理）。
