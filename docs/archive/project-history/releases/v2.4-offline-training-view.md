# V2.4 离线训练视图：从真实轨迹到 SFT 样本与偏好对（已归档）

> 状态：最小投影层已实现；产物为 offline teacher candidates，不是 on-policy RL rollouts。

## 目的

把真实 Harness 轨迹变成可训练数据，支撑两条离线路径：

```text
AgentEpisode
  → project_episode_to_rollout() → RolloutRecord   （SFT/蒸馏候选）
  → build_preference_pairs()     → TrajectoryPreferencePair （DPO/SimPO 类偏好对）
```

## 投影语义

`RolloutRecord` 字段只填充可观测部分：

```text
trajectory_id = episode_id
task_id / model identity / harness identity
verifier_status / reward（仅 VALID 时使用 verifier score）
rollout_status / termination_reason
tool_events（TOOL_CALL/TOOL_RESULT 映射）
source_payload_sha256 = episode checksum
```

诚实边界：

- `token_ids / old_logprobs / action_mask` 保持 `None`；
- 消费者要求这些能力时，capability gate 显式失败，不伪造；
- `INFRA_INVALID` 的 Episode 永远没有 reward；
- 不把 teacher 轨迹称为 on-policy RL rollout。

## 偏好对

按 `task_id` 分组，同一任务的 valid SUCCESS 作为 chosen、valid FAILURE 作为 rejected：

```text
pair_key / chosen_episode_id / rejected_episode_id
chosen_rollout_checksum / rejected_rollout_checksum
chosen_verifier / rejected_verifier / reason
```

真实 v2.1-live fixtures 产出 3 个偏好对（control vs candidate）。

## 边界

- 离线 SFT/蒸馏/偏好优化：可用；
- 严格 on-policy RL：需要目标策略采样器接入（token ids/logprobs），capability gate 已就绪；
- 所有投影带 Episode checksum 与 lineage，可回放。
