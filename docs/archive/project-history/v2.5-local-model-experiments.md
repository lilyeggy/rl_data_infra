## 3. 本地 micro-harness（学生 harness）

为本地模型实现了一个可控 harness（这就是"harness 灰箱可控"的实证）：

```text
协议：模型每轮输出一个 JSON action
  {"action":"read","path":"..."}
  {"action":"find","pattern":"..."}
  {"action":"answer",...}（或最终纯 JSON {task_id,status,failure_count}）
流程：生成 → 解析 JSON → 安全 FS 执行 → 回传 "Tool result: ..." → 循环（≤6 轮）
system prompt = harness policy（缺文件时 find task-*.json 后读唯一文件）
```

早期协议冲突教训：user prompt 若同时说"Return only JSON"，模型会跳过工具直接回答 →
协议必须区分"工具阶段输出 action JSON"和"最终答案输出纯 JSON"。

## 4. 实验 A：零样本基线（Qwen2.5-1.5B 未训练）

任务：read missing-N.json → 恢复 → 严格答案（failure_count 2/2/3）

```text
task-1: ❌ {"task_id":"missing-task-001","status":"FAILURE","failure_count":1}
task-2: ❌ {"task_id":"1","status":"FAILURE","failure_count":1}
task-3: ❌ {"task_id":"1","status":"FAILURE","failure_count":2}
结果：0/3（模型不执行工具，直接瞎猜，task_id/failure_count 全错）
```

结论：1.5B 小模型 zero-shot 无法自主完成多步工具任务。

## 5. 实验 B：LoRA SFT（用 teacher 轨迹蒸馏）

### 数据构建

从 3 条真实 candidate 轨迹提取工具调用序列，转成小模型 chat 格式：

```text
system（harness policy）
user：Start by reading missing-N.json...
assistant：{"action":"read","path":"missing-N.json"}
user：Tool result: ERROR: file not found ...
assistant：{"action":"find","pattern":"task-*.json"}
user：Tool result: task-N.json
assistant：{"action":"read","path":"task-N.json"}
user：Tool result: {文件内容}
assistant：{"task_id":"task-N","status":"SUCCESS","failure_count":N}
```

3 个示例，最终答案均通过严格 verifier。

### 训练

```text
LoRA r=8, alpha=16, 目标模块 q/k/v/o/gate/up/down
12 epochs，lr 2e-4，batch 1，grad_accum 2
CPU 耗时：277.8s（约 4.6 分钟）
train_loss：0.04111
adapter：/root/models/qwen-sft-adapter
```

### 评估（同一 harness、同一严格 verifier）

```text
task-1: ✅ {"task_id":"task-1","status":"SUCCESS","failure_count":2}
task-2: ✅ {"task_id":"task-2","status":"SUCCESS","failure_count":2}
task-3: ✅ {"task_id":"task-3","status":"SUCCESS","failure_count":3}
结果：0/3 → 3/3 ✅
```

### 边界（诚实）

- 这是 off-policy SFT/蒸馏，不是 on-policy RL；
- 评估任务 = 训练任务（in-distribution），证明"数据→训练→verifier 验证"机制闭环；
- 泛化到未见任务需要实验 C；
- 样本小（3 条），是 reference mechanism。

## 6. 实验 C：泛化验证（训练时未见任务）【已完成】

held-out 任务：task-4（failure_count=1）、task-5（failure_count=4），同一 harness + verifier。

```text
基线模型：0/5（task-1..5 全失败，直接猜答案）
SFT 模型：5/5
  task-1..3（训练任务）✅
  task-4（未见，failure_count=1）✅
  task-5（未见，failure_count=4）✅
```

结论：SFT 学到的是**程序化能力**（read missing → find task-*.json → read → 数 FAILURE 数），
在同任务族内对未见任务泛化；不是死记 3 个训练任务。诚实边界：泛化范围是同一任务族
（同 pattern），不是跨任务类型泛化。

## 7. 实验 D：GRPO-lite（on-policy RL 冒烟）【已完成】

设计：

```text
策略：本地模型（SFT 权重为起点）+ LoRA 可训练
采样：temperature 采样 G=4 条 rollout/task（本地，带 logprob）
reward：verifier 通过=1；恢复路径成功=0.5；否则=0
GRPO：组内 advantage 归一化 + ratio clip + KL(πθ||πref)
评估：训练前后同一 harness + verifier（task-1..5）
```

### GRPO-lite 结果【已完成】

```text
STEP 0 采样（temp 0.4）：task-1/2 全 1.0；task-3 = 1.0, 0.5, 0.5
STEP 1 采样：task-3 全 1.0（on-policy 强化后恢复行为被加强）
STEP 2：完成
训练后贪心评估（同一 harness + verifier）：
  task-1..5 全部成功 → 5/5 ✅
```

结论：
- on-policy 闭环在 CPU 服务器上真实跑通：本地模型采样（带 logprob）→ verifier reward
  → 组内 advantage → LoRA 更新 → 再评估；
- SFT 已在这 5 个任务上饱和（贪心 5/5），GRPO 的价值是“在不回归的前提下完成 on-policy
  学习”，并用 step0→step1 的采样分布变化证明梯度信号真实生效；
- 要证明 GRPO 能“超越 SFT”，需要 SFT 失败的更难任务（诚实边界，未声称）。

### GRPO-lite 实现要点

```text
policy：SFT merge 权重 + 新 LoRA（初始为 0 → 起点= SFT）
reference：同一模型 disable_adapter 的 logprob（KL 锚，单模型省内存）
reward：verifier 通过=1.0；恢复路径成功（读过任务文件）=0.5；否则 0
advantage：按 task 组内 (r-mean)/(std+eps)，std≈0 时置 0
loss：-min(ratio, clip(ratio,1±0.2))*adv + β*KL(πθ‖πref)，逐 token
内存：逐 rollout 梯度累积（避免批量 padding 激活 OOM，cgroup 上限 42GB）
```

初版教训：双模型（policy+reference）在批量 forward/backward 时激活内存超 cgroup 42GB 被静默 kill；
temperature 0.7 采样全部失败 → 组内无信号；改为 temp 0.4 + process reward。

### GPU 迁移踩坑（已修复）

1. **off-by-one 标签 bug（最重要）**：repo 版 sft_train 曾写 `labels[t]=ids[t+1]`，
   而 HF Trainer 内部会 shift（CE(logits[:,:-1], labels[:,1:])），导致实际预测 `ids[t+2]`、
   掩码错位一格 → loss 卡在 ~0.9 不收敛。修复：`labels[i]=ids[i] if trainable[i] else -100`。
   症状可诊断：初始 loss 一致 ~20.6，多 epoch 只降到 ~0.9。
2. torch cu124 源在新疆不可达 → 用 aliyun PyPI（自带 CUDA 13 运行时，快）。
3. 评估路径：bf16 base + fp32 adapter 混合可能劣化，`LOCAL_MODEL_FP32=1` + eager attention 更稳。
4. shell 双引号内 `$v` 会被本地展开 → 输出目录名变成空（v6/v7 写进同名目录），
   远程循环变量要用单引号外层或显式拼接。

诚实边界：SFT 最好种子 5/5、其余种子 4/5（task-3 计数），GRPO 4/5——1.5B 对 5 条记录
的 failure_count 计数存在随机错误，这是模型能力边界，不是数据面问题。

## 11. 面试要点

- 真实 teacher（Pi+deepseek）→ canonical 轨迹 → verifier 过滤 → SFT → 0/3→3/3；
- harness 是可观测黑箱 + 可控灰箱：协议（prompt）设计直接影响小模型能力；
- online（GRPO）需要本地采样器 + logprobs + verifier reward，我们已具备；
- 诚实边界：in-distribution 机制验证、小样本、off-policy。
