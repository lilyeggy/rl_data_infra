# V2.1 教学复盘：深层 Trace 与 Harness 决策可观测性（已归档）

> 状态：decision capture 接口与 bounded FILE_NOT_FOUND recovery policy 已实现；正在接入 V2.1 replay。
> 这一阶段不修改 V1/V2 canonical contract，也不放宽 V2 Regression Gate。

## 1. V2.1 解决什么问题

V2 能可靠观察 Harness 的外部行为，例如：

```text
TOOL_RESULT(FILE_NOT_FOUND)
→ TOOL_CALL(read, same path)
```

但黑盒 trace 不能证明 Harness 内部究竟做了什么决定。V2.1 将增加可选的 Hook-enabled decision facts，使链路能够表达：

```text
TOOL_RESULT
→ HARNESS_DECISION
→ TOOL_CALL / TERMINATION_DECIDED
```

这样系统可以区分：

- Harness 选择了 retry；
- Harness 选择了 discovery；
- Harness 选择了 terminate；
- Harness 没有 decision capture，内部行为仍然 `NOT_OBSERVABLE`；
- 外部 action 与 Harness policy 不一致。

## 2. 为什么属于 Agent Infra

Decision event 是 Harness Runtime 的遥测，不是任务业务结果。它支撑：

- retry/recovery budget；
- policy versioning；
- decision-to-action causal linkage；
- failure attribution；
- deterministic replay；
- Harness A/B comparison；
- policy regression testing。

没有 decision evidence，我们只能说“观察到了重复动作”，不能可靠回答“为什么 Harness 允许重复动作”。

## 3. 与 V1/V2 的关系

V1/V2 数据流保持不变：

```text
TraceEvent
  → AgentEpisode
  → Metrics / Diagnosis / Comparison / Gate
```

V2.1 只是增加已有 `EventType` 中的 Hook 事件，并把 policy 事实放入 `attributes`：

```text
TOOL_RESULT
  → HARNESS_DECISION
  → TOOL_RESULT / TOOL_CALL
  → TERMINATION_DECIDED
```

Decision fact 和 Diagnosis 必须分离：

```text
HARNESS_DECISION = 原始事实
OBSERVED_TOOL_ERROR_LOOP = 派生诊断
```

## 4. 当前接口边界

`src/capture/recorder.py` 中的 `HarnessHook` 负责把 Harness 已经暴露的 decision 写成 append-only `TraceEvent`。它可以附带：

- `trigger_event_ids`；
- `policy_name` / `policy_version`；
- `scope_key`；
- `budget_before` / `budget_after`；
- `cache_hit`；
- decision-specific details。

没有 Hook 时，调用方不能用外部动作伪造这些字段，也不能把能力声明为已存在。

## 5. Bounded FILE_NOT_FOUND policy

`src/recovery/file_not_found_policy.py` 已实现无隐式全局状态的 bounded policy。它接收 immutable input snapshot，输出可 checksum 和 replay 的 decision：

```text
FILE_NOT_FOUND
→ 提取 basename 或 pattern
→ 最多一次有界 discovery
→ 候选唯一时 read
→ 候选不唯一时稳定选择或终止
→ 缓存 discovery 结果
→ 相同 scope 不重复搜索
→ budget 耗尽后终止
```

核心不变量：

1. 只有结构化 `FILE_NOT_FOUND` 才触发；
2. discovery 在同一 scope 内最多一次；
3. cache 与 budget 不通过隐式全局状态共享；
4. 候选选择规则确定性；
5. budget 耗尽后不再进入工具循环；
6. 相同输入得到相同 decision；
7. policy 不修改 raw events；
8. decision 可以关联到触发 event，但不能替代 diagnosis。

## 6. Contract 与实现边界

当前 policy contract 定义：

```text
RecoveryInput
  - error_code
  - error_path
  - scope_key
  - discovery_cache
  - remaining_discovery_budget
  - trigger_event_ids

RecoveryDecision
  - action: DISCOVER / READ / TERMINATE / NO_ACTION
  - reason_code
  - arguments
  - selected_candidates
  - budget_before / budget_after
  - cache_hit
  - policy_version
```

policy 的目的，是在不改变 canonical TraceEvent/AgentEpisode 的前提下被单元测试、重放和接入 Harness Hook。`RecoveryController` 负责单个 Episode 内的 cache、attempted scope 和 budget 生命周期；`RecoveryExecutionAdapter` 再把 action 转成 `ToolDispatchRequest`，交给受控 executor，并限制一次 recovery 最多一个 discovery 和一个 read。controller/executor 都不直接修改 raw event；Harness runtime 应通过 `HarnessHook` 将实际 decision 作为原始事实记录。

## 7. V2.1 验收

保持 `configs/gates/reference-v2.json` 不变：

```text
success = 3/3
OBSERVED_TOOL_ERROR_LOOP = 0
token increase ≤ 20%
latency increase ≤ 25%
```

还必须验证：

- decision event 能引用真实 trigger event；
- discovery budget 和 cache 行为可重放；
- 达到 budget 后没有新的工具循环；
- raw events 仍 append-only；
- `FAILURE + VALID`、`UNKNOWN + INFRA_INVALID` 和 `NOT_OBSERVABLE` 语义没有变化；
- V2 baseline fixture 仍然输出原有 REJECT 结果。
