# V2.3 教学复盘：生产级采集、存储与吞吐（已归档）

> 状态：partitioned ingestion/filesystem adapter 已实现；分布式生产存储仍需后续替换 adapter。

## 1. V2.3 解决什么问题

V1/V2/V2.1/V2.2 已经建立了执行语义和派生视图，但原始存储仍是单进程本地 JSONL。V2.3 开始冻结 storage/ingestion boundary：

```text
producer
  → ingestion boundary
  → run/episode partition
  → event_id idempotency
  → quarantine
  → partition manifest
  → replayable derived jobs
```

## 2. PartitionedEventStore

当前提供 dependency-free filesystem adapter 和可替换的 `StorageBackend` object boundary：

```text
storage/
└── partitions/
    └── run-<digest>/
        └── episode-<digest>/
            ├── identity.json
            ├── raw-events.jsonl
            └── partition-manifest.json
```

分区路径使用 checksum，不直接拼接用户提供的 run/episode ID，避免路径逃逸。

## 3. Ingestion semantics

`PartitionedEventStore.ingest()` 支持：

- at-least-once input；
- exact duplicate by `event_id + checksum`；
- conflicting duplicate quarantine；
- batch grouping by run/episode；
- bounded flush through the underlying writer；
- partition manifest；
- reload and read-back。

冲突事件进入：

```text
quarantine.jsonl
```

不会写进 raw partition。

## 4. Manifest 与 lineage

每个 partition manifest 记录：

```text
run_id
 episode_id
event_count
event_ids
event_checksums
events_checksum
raw_events_path
storage_mode
```

manifest 是派生 storage metadata，不改变 raw event。重新加载时会重新建立 global event index，并再次检查冲突。

## 5. Queue/backpressure

`BoundedEventQueue` 按 event 数量限制 pending memory，满时提供：

```text
non-blocking put → BackpressureError
blocking put → wait/timeout
```

`IngestionWorker` 只负责 drain queue 并调用 storage ingest，不改变 event semantics。

## 6. Derived compaction

compaction 只产生：

```text
compacted-events.jsonl
compaction-manifest.json
```

raw partition 永远不重写。malformed raw partition 不会生成完整 compacted view。

## 7. Schema registry

`StorageSchemaRegistry` 要求未知 schema version 显式注册 migration。没有 migration 时：

```text
UNKNOWN_SCHEMA_VERSION
→ reject/quarantine
```

不会静默 coercion。

## 8. Ingestion latency

V2.3 提供 deterministic `mean/p95/p99/max` summary，用于 load evidence。小样本 smoke 的 percentile 不能当作生产容量承诺。

## 9. 当前 durability 边界

当前 adapter 使用：

```text
append
flush
fsync
atomic manifest replace
process-local lock
```

它可以作为容器 Job 或单 worker 的 durable filesystem baseline，但不能声称：

```text
distributed exactly-once
multi-writer transaction
object-store atomic commit
cross-region durability
```

生产环境需要将 `StorageBackend` 替换为 queue/object-storage/transactional-log adapter，同时保持同样的 ingestion result、idempotency 和 quarantine semantics。

## 11. HTTP ingestion baseline

当前可运行：

```bash
python3 -m src.cli serve-storage \
  --root artifacts/v2.3-http-storage \
  --host 0.0.0.0 \
  --port 8080
```

接口：

```text
POST /v1/events
GET  /healthz
GET  /metrics
```

`POST /v1/events` 支持 JSON object、JSON array 或 NDJSON。schema error 返回 400，queue 满返回 429。后台 worker 将 accepted events 写入 `PartitionedEventStore`。

当前 HTTP service 明确是 container baseline：没有 auth/TLS/multi-tenant/remote object storage，生产部署必须由网关和云平台补齐。

## 12. 下一步生产化

V2.3 后续仍需完成：

- multi-process/multi-worker ingestion；
- queue and backpressure；
- object-store artifact adapter；
- partition compaction；
- schema registry/migration；
- load/fault injection；
- retention and access control；
- P95/P99 ingestion latency；
- crash recovery across worker restart；
- object backend 的 conditional put/version semantics。

这些工程扩展不能改变 V1/V2/V2.1/V2.2 的 canonical semantic contract。
