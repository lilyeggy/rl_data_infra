# V2.2 教学复盘：Multi-Agent 因果关系与训练语义（已归档）

> 状态：V2.2 graph/training view 已实现；当前 evidence 使用明确标记的 synthetic multi-agent fixture。
> 未取得真实生产 multi-agent artifact 前，不声称完整覆盖所有 Agent runtime 或训练算法。

## 1. V2.2 解决什么问题

单 Agent 的 `TraceEvent → AgentEpisode` 可以描述一次执行，但多 Agent 运行还需要回答：

```text
谁发起了 action？
谁拥有 tool call？
谁是哪个 Agent 的 parent？
消息从谁传给谁？
哪些 branch 并发？
reward 属于哪个 Agent？
哪个 action 获得多少 credit？
哪些 action 能进入哪个训练视图？
```

这些语义不能根据 span、时间顺序或共享 Episode 自动猜测。

## 2. 派生 graph，不修改 canonical contract

V2.2 使用：

```text
AgentEpisode
  ↓ explicit event attributes
MultiAgentExecutionGraph
```

原始事件可以在 `attributes` 中携带：

```text
agent_id
parent_agent_id
agent_role
policy_id
policy_revision
branch_id
parallel_group_id
message_to_agent_id
reward_owner_agent_id
reward_scope
```

这些字段只有在 producer 明确提供时才被使用。缺失时保留：

```text
NOT_OBSERVABLE
或
INSUFFICIENT_EVIDENCE
```

## 3. Graph relation

当前 graph 支持：

```text
PARENT_CHILD
MESSAGE_ROUTE
TOOL_OWNERSHIP
REWARD_OWNERSHIP
CREDIT_ASSIGNMENT
```

每条 relation 都保留：

```text
source_agent_id
 target_agent_id
 evidence_event_ids
 attributes
```

例如：

```text
agent-orchestrator
  --MESSAGE_ROUTE(evt-message)→
agent-researcher
```

```text
agent-researcher
  --TOOL_OWNERSHIP(evt-tool-call)→
read tool
```

## 4. Evidence status 必须按字段独立判断

一个运行可以是：

```text
agent_identity: OBSERVED
parent_child: OBSERVED
message_routing: OBSERVED
branch_concurrency: NOT_OBSERVABLE
reward_ownership: INSUFFICIENT_EVIDENCE
credit_assignment: NOT_OBSERVABLE
```

不能因为 `agent_id` 已知，就自动推断：

- parent/child；
- branch/concurrency；
- reward ownership；
- credit assignment。

图的整体状态：

```text
OBSERVED
NOT_OBSERVABLE
INSUFFICIENT_EVIDENCE
INVALID
```

其中：

- `NOT_OBSERVABLE`：没有对应采集能力或没有任何事实；
- `INSUFFICIENT_EVIDENCE`：部分事实存在，但无法完整判断；
- `INVALID`：metadata 冲突、未知 parent 或环；
- `OBSERVED`：required identity/causal facts 一致且明确。

## 5. MultiAgentTrainingView

V2.2 不把多 Agent Episode 强制压缩成一个 `RolloutRecord`，而是先生成 per-agent view：

```text
MultiAgentTrainingView(agent-orchestrator)
MultiAgentTrainingView(agent-researcher)
```

每个 view 包含：

```text
agent identity
role
policy identity
observation ownership
action ownership
reward ownership
credit assignment
policy relation
SFT eligibility
on-policy RL eligibility
missing capabilities
exclusion reasons
evidence event IDs
```

## 6. Eligibility 规则

### SFT candidate

需要：

```text
Episode integrity = COMPLETE
execution validity = VALID
task status = SUCCESS
graph status = OBSERVED
agent observation ownership = OBSERVED
agent action ownership = OBSERVED
```

### On-policy RL candidate

除上述条件外，还需要：

```text
target policy identity matches
agent-level reward ownership is observed
agent-level credit assignment is observed
MODEL_TOKEN_IDS
MODEL_LOGPROBS
```

因此本阶段 synthetic fixture 的结果是：

```text
SFT candidates: 2
on-policy RL candidates: 0
```

这不是失败，而是正确拒绝了缺少策略和 token evidence 的数据。

## 7. Synthetic fixture 的边界

当前 fixture 显式包含：

```text
orchestrator
└── researcher
```

以及：

- parent-child；
- message route；
- tool ownership；
- branch metadata；
- episode reward owner；
- credit assignment status is explicitly absent and therefore `NOT_OBSERVABLE`；
- per-agent policy identity。

它只证明 contract、graph builder、lineage 和 training eligibility view 能工作，不证明：

- 所有真实 multi-agent Harness 都使用相同语义；
- reward credit assignment 已经解决；
- multi-agent RL batch 已经生产；
- benchmark 已经提升。
