## 实施顺序与停止条件

1. **修复真实多轮桥接**：Pi 协议代理调用 verl `AsyncLLMServerManager.generate`，初始 prompt 用冻结模板编码；后续保留原生生成 token，只追加工具观察和模板边界。检测消息历史改写、工具结果错配、schema 改变、截断与超预算。复用固定上游 Hermes parser；禁止宽松 JSON 恢复。CPU 测试后，再用服务器真实 tokenizer / verl 类型验证。
2. **收紧训练前认证**：独立 episode、原生 uid 分组、每组同任务且奖励有差异；任何无效样本停止。核对认证序列与实际输出张量，证据按 generation 单独存放。策略身份必须绑定实际 checkpoint 和同步证据，不能以服务名或计数器代替。
3. **整理可执行基线**：核对冻结模型、上游版本及现存兼容补丁；保存实际 lock、配置、命令、资源快照。修复既有测试并执行服务器真实接口 CPU 检查。原计划的隔离、恢复、预算要求仍然有效。
4. **最小真实验证**：先一条至少两轮、含真实工具结果的 Pi rollout，通过原生 token 对齐；再完整四 episode group，通过认证后才启动原生更新。没有真实组内学习信号则停止，不造奖励、不复用历史轨迹。
5. **原生两轮闭环**：P0→P1→P2，原生保存、同步、checkpoint 恢复，更新后 Pi rollout；记录参数差异和 logprob 对照。固定 holdout 对比，效果与接入分别报告。
6. **收尾**：仅清理本运行登记资源，更新机器和人工验收报告，未验证项目明确 NOT_RUN/BLOCKED。
