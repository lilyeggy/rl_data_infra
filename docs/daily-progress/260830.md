# 2026-08-30

今天重新核对了 Polar 对比口径，确认旧的本地 benchmark 实际是宿主机 Pi Direct，不是完整 Data Plane；旧报告已标记废弃。新增真实端到端 runner，使任务必须经过 Docker Sandbox、Pi、Model Proxy、Trace/Evidence、Verifier、Finalizer 和 ExecutionBundle，并在 A6000 上完成 c1/c4/c8 实测。

参考 VRAM-Aware-Harness 落地了 `FAST+runc` 与 `SECURE+runsc` 两种 Sandbox 契约。Secure 模式会检查 Docker 是否注册 runsc，缺失时 fail-closed，不允许静默回退；A6000 当前只注册 runc，因此本轮性能测试使用 Fast 模式，暂未安装 gVisor。

公平对比固定了同一 Pi 0.84.2 预热镜像、Qwen2.5-Coder-14B checkpoint、vLLM tool-compat endpoint、任务与 sampling，并修复 Polar 新版 `return_token_ids` 参数与当前 vLLM 0.6.1 的兼容问题。最终单轮 verified throughput：c1 本地 0.0339/s、Polar 0.1250/s；c4 本地 0.1453/s、Polar 0.2000/s；c8 本地 0.4823/s、Polar 0.3500/s。该结果说明本地路径只在 c8 饱和场景出现约 1.38 倍观测优势，c1/c4 反而更慢；由于模型调用轮数会波动，下一步应增加重复试验并拆分模型生成、Sandbox、编排和 evidence 开销。

收尾时完成了 Sandbox、Model Proxy 与 LocalExecution 的 20 项定向测试，全部通过；完整测试集中可运行的 333 项也已通过，另 2 项仅因本机 Python 未安装 pytest 而无法导入。A6000 已产出完整公平对比数据，但最终文件回同步阶段 SSH 服务连续在密钥交换时主动断开，待服务器 SSH 恢复后只需同步最新测试与报告脚本，不影响已经落盘的远端 benchmark 结果。
