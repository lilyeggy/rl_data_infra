重复结果显示 Local 的 verifier 通过率为 100%，Polar 在 c4 为 91.67%、其余为 100%。verified throughput 均值：c1 Local 0.0940/s、Polar 0.0905/s；c4 Local 0.1908/s、Polar 0.1944/s；c8 Local 0.3396/s、Polar 0.4955/s。配对 Local/Polar 吞吐比均值为 c1 1.018、c4 1.060、c8 0.706。

因此项目不能再宣称“高并发下明显快于 Polar”：单次 c8 的 1.38x 是波动样本，三轮后 c8 反而低于 Polar。当前可靠结论是：Data Plane 在完整 evidence、verifier 与 ExecutionBundle 的前提下能保持 100% 验证通过，但性能层面 c1/c4 大体接近平局、c8 存在明确优化空间；下一步需要分段测量模型生成、Sandbox 启动、Harness、Verifier 与 evidence/finalization 的耗时。

随后依据 host-owned raw events 和 model evidence 完成分段定位。Local 每 Episode 的 c1/c4/c8 模型耗时为 11.12/14.12/15.08 秒，模型调用轮数为 2.67/3.00/3.29；容器启动、工具间隔、Verifier/Finalization 与 trace 外开销合计增长不足 1 秒。Polar 保存的 response record 数为 2.33/2.83/2.75，run 时间为 10.90/11.62/9.59 秒。主要问题是 Local 的 Controlled 路径为保证 RL 可用性强制请求逐 token logprob、缓冲非流式响应、同步持久化 evidence 后再回放 SSE；Polar 当前没有承担相同证据采集成本，且 c8 的轨迹平均少约 0.54 个响应轮次。因此现有数据是“完整可训练数据生产”对比，不能被解读为纯编排性能对决；后续应做 evidence-on/off 消融、Polar evidence-equivalent 对齐和 vLLM max-num-seqs 扩容实验。

已完成第一轮三次的 Evidence on/off 消融：关闭 logprob 没有稳定提高 c8 吞吐（completed throughput：on 0.3984/s、off 0.3391/s），而逐轮差异与模型调用数高度相关。为避免 Agent 采样路径不同掩盖基础设施开销，Model Proxy 新增 `default_sampling_seed`，会向未显式指定 seed 的 vLLM 请求注入固定 seed；该实现通过 8 项定向测试。固定 seed 的新三轮消融已在 A6000 启动，完成后再根据可归因结果决定是否改共享 Proxy 或 vLLM 参数。

补充完成 `docs/benchmarking-fairness-protocol.md`：参考 vLLM/GenAI-Perf 的 TTFT、TPOT、token throughput 与 goodput，以及 MLPerf 的 offline/server 场景划分，明确以后比较必须分为推理内核、固定轨迹回放、端到端可信数据生产三层。`session/s` 只作为运营指标；主指标改为 verified episode、SFT token、RL-usable token 的 goodput，并要求 Polar 与 Local 在 Evidence 语义上先对齐再宣称 speedup。

读取 Polar 官方仓库后补充 `docs/polar-metric-mapping.md`。Polar 训练侧聚合的是 queue/init/run/postrun 阶段均值、reward mean/std、rollout success、evaluator resolved rate、policy staleness 和 trajectory record/trace count，并暴露 Gateway 的各阶段 inflight/queue depth；它并不把 session/s 作为唯一核心指标。固定 seed Evidence on/off 消融已完成，completed throughput 在 c1/c4/c8 基本相当（RL Evidence 0.1916/0.6145/1.0908，off 0.1923/0.6298/1.0315），说明逐 token logprob 采集不是主瓶颈；但该固定 seed 下任务 verifier 全失败，结果只能用于热路径开销诊断，不能用于可信训练数据 goodput。

实现 `LocalRolloutPool`/`RolloutPoolMetrics`，并把首个模型请求定义为 init→run、Harness 返回定义为 run→postrun，导出 queue/init/run/postrun 的 per-episode 与 mean/p95 指标；10 项定向测试通过。A6000 c1 冒烟成功写入 pool metrics（queue 0.45ms、init 644ms、run 4.30s、postrun 252ms）。benchmark 同时新增 completed token、verified SFT token、verified RL token goodput；真实 c1 有 86 个可追踪 RL token，但 verifier failed，因此 verified SFT/RL goodput 均严格为 0，证明质量 Gate 不会把不可用数据计入产能。

完成固定工作量回放实验，消除 Agent 轨迹长度和 Sandbox/Harness/Verifier 的混杂因素：相同冻结 prompt、vLLM、seed、128 token 上限和上游 logprob 请求，比较直连 vLLM 与 Proxy+durable evidence。三轮、c1/c4/c8、每臂 12 请求均成功。Proxy 的 completion-token goodput 保留直连的 96.2%/90.5%/88.1%；c1/c4 p95 E2E 平均仅增加 18.8ms/36.4ms。c8 有一次 direct-vLLM p95 异常，不能把均值反转解读成 Proxy 更快，已在 `docs/proxy-replay-benchmark-260831.md` 明确记录，并保留全部原始配对 JSON。

Polar live evidence probe 在相同 vLLM 上完成 4/4。发现 vLLM 0.6.1 不接受 Polar 新版请求字段 `return_token_ids`，但已通过现有兼容代理从服务端返回的 `logprobs.content[].token="token_id:<id>"` 规范化生成 `choice.token_ids`，不修改 Polar 内核。第二轮 Polar probe 4/4 通过，持久化 completion 已同时包含 `token_ids` 与 `logprob`；因此后续 Local/Polar 可以进行 response-level token/logprob evidence 对齐。prompt-logprob 探测会触发该旧版 vLLM 的采样断言崩溃，已记录为 serving 版本限制并重启服务；不能将其误归因于 Data Plane。

完成两轮 c1/c4/c8 的 Local–Polar response-evidence 对齐端到端批次。Polar verifier 通过率为 c1 100%、c4/c8 87.5%；Local 所有 Episode 均 `COMPLETED + COMPLETE`、带 response token-id/logprob evidence，但固定 seed `20260831` 下 verifier 通过率为 0%。因此 Local 只可报告 completed 产能（c1/c4/c8 为 0.1836/0.6161/1.0230 episode/s，15.79/52.98/87.97 completion token/s），verified SFT/RL goodput 必须严格为 0；不得将该批次解释为 Local 性能劣于 Polar。该现象是严重的 Harness/模型执行行为回归，下一步优先回放失败轨迹，区分模型未正确调用工具、工具调用被兼容层错误解析、还是 Pi/容器工作目录语义与 Polar 不一致。

回放定位结论：这不是 Proxy、Sandbox 或 verifier 问题。模型将真实初始内容 `return 0` 幻觉为 `return None`，导致 Pi 的 exact-text edit 失败；且把存在依赖关系的 edit 与 test 同轮提交。将 benchmark 任务合同改为显式给出初始文件内容，并要求 edit 与 test 分为先后两个 tool-call turn 后，同一 fixed seed 的 Local c1 恢复 1/1 通过并产出 84 个 verified RL-usable tokens。随后重跑两轮 c1/c4/c8 response-evidence 对齐的完整 Local–Polar 对比：Local verified throughput 为 0.1955/0.6260/1.0534 episode/s，verifier 100%；Polar 为 0.1339/0.5000/0.7626 episode/s，verifier 为 100%/100%/93.75%。该结论仅适用于当前固定 Pi、Qwen 14B、任务合同、A6000 和两轮样本；完整原始结果位于 A6000 `sft-runs/evidence-equivalent-e2e-260831-v3/`。
